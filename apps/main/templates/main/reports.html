Control Status

Passing The control's current measured value meets or exceeds the target threshold.
Failing The control's current measured value is below the target threshold. Action is required.
Not Measured No evaluator has been run for this control, or it requires manual review. This does not indicate a passing or failing state.
M Manual The automated evaluator has been overridden. Status and value were set manually, typically backed by off-system evidence or a review record.

Authentication Strength Levels

Level Description Examples
Phishing Resistant Hardware-bound credentials that cannot be intercepted or replayed by a phishing attack. Strongest available. FIDO2, Windows Hello for Business, hardware security keys
Multi-factor Authentication Two or more factors required. Phishing-susceptible but still significantly stronger than password alone. Authenticator app (TOTP), push notification
Deprecated Authentication methods considered insecure or phased out by current standards. Should be disabled or migrated. SMS one-time codes, voice calls, app passwords
None Password only. No second factor registered or enforced. Highest risk — account is vulnerable to credential compromise. Username + password with no MFA method registered

Key Terms

Term Definition
Cloud-Only User A user account created directly in Entra ID, not synchronized from on-premises Active Directory. Subject to Entra ID password policies only.
Compliant Device An endpoint that meets all required security policies as defined in Device Compliance Settings for its OS platform and enrolled integrations.
Hybrid User A user account that originates in on-premises Active Directory and is synchronized to Entra ID. Password policy is controlled by AD (default domain or an FGPP/PSO if applied).
Integration A configured vendor connection that pulls security data (devices or users) into the platform. Examples: Microsoft Intune, CrowdStrike Falcon, Sophos Central.
Persona A user classification used to segment identity risk reporting. Users are assigned to personas via group membership. Examples: Privileged, Service Account, Standard User.
Resultant PSO The effective Fine-Grained Password Policy applied to an AD user after evaluating all group and user-level PSO assignments and precedence values.
